- 2. Requerimiento de los sistemas multimedia
  - Cuestiones fundamentales que debe gestionar un sistema multimedia:
    - Cómo representar y almacenar información temporal, por ejemplo, mediante marcas de tiempo (timestamps) en audio y vídeo.

    - Cómo representar y procesar digitalmente todos los datos – Conversión AD-DA, muestreo (sampling), etc.

  - Capacidad de procesamiento muy alta. Necesaria para lograr procesamiento de grandes cantidades de datos y entrega de datos multimedia en tiempo real – Hardware especializado.
  - Sistema de ficheros preparado para multimedia. Necesario para producir datos multimedia en tiempo real – Vídeo-Audio streaming, tecnología RAID.
  - Software/hardware especializado.
  - Representación de la información. Formato de ficheros que soporten multimedia, sean fáciles de manejar, y permitan compresión y descompresión en tiempo real.
  - E/S eficiente. La E/S al subsistema de ficheros debe ser eficiente y rápida, tanto para grabación en tiempo real como para reproducción.

[BLOQUE 7] Streaming y descarga tradicional
- Streaming:
- Definición:
- Distribución de multimedia a través de una red de manera que el usuario consume el producto al mismo tiempo que se descarga.
- El termino streaming se refiere a: una corriente continua (sin interrupción).
- Este tipo de tecnología funciona mediante un búfer de datos que va almacenando lo que se va descargando en el dispositivo del usuario para luego mostrar el material descargado.
- Se envía la información a través de la red y el cliente la reproduce en tiempo real al recibirla
- Audio / Vídeo Tiempo real
- SERVIDOR RED CLIENTE
- Descarga tradicional:
  - Los ficheros de audio o vídeo se almacenan en el servidor y se transfieren mediante protocolos como HTTP.
  - El cliente descarga el fichero completo a disco antes de reproducirlo.
  - No hay streaming: hay que esperar a que la descarga termine para empezar a reproducir.
  - Ventaja: una vez descargado, no depende de la red para reproducirse.
  - Desventaja: requiere más espacio en disco y un tiempo de espera inicial largo.
  - Ejemplos: descargar una canción en MP3, un vídeo guardado en el dispositivo, o instalar un videojuego desde una tienda digital.
- Streaming:
  - Los datos se transfieren segmentados y se pasan al reproductor a medida que llegan, sin esperar a la descarga completa.
  - El sistema calcula el tiempo de búfer necesario según la velocidad de recepción, para evitar cortes en la reproducción.
  - Requiere garantizar la calidad de servicio (ancho de banda y latencia) para una reproducción fluida.
  - Puede ser en directo (eventos en tiempo real) o a la carta (contenido bajo demanda, como vídeo o música).
  - Ventaja: reproducción casi inmediata, sin la larga espera inicial de la descarga tradicional.
  - Desventaja: la calidad de la reproducción depende de la conexión en cada momento.
  - Ejemplos: Netflix, YouTube y Spotify.

[BLOQUE 13] Arquitectura streaming: cliente y buffer
- Arquitectura Streaming. Cliente
- Componentes:
- Recepción.
- Recibe la información solicitada por el usuario.
- Presentación.
- Reproduce la información recibida de forma temporizada.
- Proporciona un interfaz para que el usuario interaccione.
- Buffer.
- Se utiliza para controlar la calidad del servicio.
- El buffer se carga antes de comenzar la reproducción
- Cuando el buffer se vacía, se detiene la reproducción para recargarlo (fallo de reproducción).
- El buffer amortigua posibles retrasos en la llegada de paquetes (por problemas en la red o sobrecarga en el servidor).
- Habitualmente existen buffers tanto de audio como de vídeo.
- El tamaño del buffer debe balancear el tiempo de arranque y calidad de reproducción.
- Arquitectura streaming: el buffer absorbe el jitter

[BLOQUE 16] Caso Netflix: arquitectura de reproducción
- Al Reproducir contenido en la aplicación o dispositivo, el Cliente hablará tanto con Backend en AWS como con OCA en Netflix CDN para transmitir videos.
  - 1. Los OCA envían constantemente informes de salud sobre el estado de la carga de trabajo, la capacidad de enrutamiento y los videos disponibles al servicio de control de caché que se ejecuta en AWS EC2
- 2. Se envía una solicitud de reproducción desde el dispositivo cliente al servicio de aplicaciones de reproducción de Netflix que se ejecuta en AWS EC2 para obtener las URL con la transmisión del video.
  - 3. El servicio de aplicaciones de reproducción debe determinar que la solicitud de reproducción sea válida para poder ver el video en particular: verificar el plan del suscriptor, la licencia del video ,etc.
- 4. El servicio Playback Apps habla con el servicio Steering que también se ejecuta en AWS EC2 para obtener la lista de servidores OCA apropiados del video solicitado.
  - 5. De la lista de 10 servidores OCA diferentes devueltos por el servicio Playback Apps, el cliente prueba la calidad de las conexiones de red a estos OCA y selecciona el OCA más rápido y confiable para solicitar archivos de video para la transmisión.
- 6. El servidor OCA seleccionado acepta solicitudes del cliente y comienza a transmitir videos.

[BLOQUE 17] Caso Netflix: arquitectura backend y objetivos finales
- Backend maneja:
- El registro.
- Inicio de sesión.
- Facturación.
- Tareas de procesamiento complejas como la transcodificación de video.
- Recomendaciones personalizadas.
- Etc.
- Netflix emplea la arquitectura de microservicios para su sistema basado en la nube.
- 1. El cliente envía una solicitud de reproducción al backend que se ejecuta en AWS. AWS Load balancer (ELB) maneja esa solicitud.
  - 2. AWS ELB enviará esa solicitud al servicio API Gateway que se ejecuta en instancias AWS EC2.
- Se aplicarán algunos filtros predefinidos correspondientes a la lógica de negocio y se reenviará a la API de la aplicación para su posterior manejo.
- 3. El componente API de la aplicación es la lógica de negocio central detrás de las operaciones de Netflix. Tipos API:
  - API Registro.
  - API recomendaciones.
  - API Player.
  - 4. Play API llamará a un microservicio o una secuencia de microservicios para cumplir con la solicitud.
    - ServIcio Playback Apps
    - Servicio Steering
    - Servicio Cache Control
- Los microservicios son en su mayoría pequeños programas sin estado y pueden llamarse entre sí.
- 5. El resultado tras la ejecución se puede almacenar en una caché, para permitir un acceso más rápido.
  - 6. Los microservicios pueden guardar u obtener datos de un almacén de datos durante su proceso.
- 7. Los microservicios pueden enviar eventos para rastrear las actividades del usuario u otros datos a Stream Processing Pipeline.
  - 8. Los datos que salen de Stream Processing Pipeline pueden ser persistidos en otros almacenes de datos:
    - AWS S3
    - Hadoop HDFS
    - Cassandra
    - etc.
- Streaming Caso NetFlix (Objetivos finales)
  - Garantizar una alta disponibilidad para los servicios de transmisión a escala global.
  - Diseñar un sistema en la nube capaz de recuperarse automáticamente de fallos o interrupciones del sistema.
  - Minimizar la latencia de transmisión para cada dispositivo compatible en diferentes condiciones de red.
  - Admitir escalabilidad con un gran volumen de solicitudes.
